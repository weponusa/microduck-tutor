## 0. 先把直觉摆正

强化学习不是"喂一堆标注数据让模型学规律"。它只给三样东西：

1. 一个**能改状态的环境**（物理引擎、游戏、真实机器人）
2. 一个**会打分的规则**（奖励）
3. 一个**可以反复试的机会**

然后它自己试。所以它的学习材料不是数据集，是**自己搞砸的经历**。

| | 监督学习 | 强化学习 |
| --- | --- | --- |
| 你给什么 | 输入 + 正确答案 | 环境 + 奖励函数 |
| 数据哪来 | 人标注 | 自己试出来 |
| 反馈 | 每步都有标准答案 | 常常几十步后才见分晓 |
| 典型失败 | 过拟合、数据脏 | 奖励被钻空子、训练不收敛 |
| 你的鸭子 | — | "别摔"这件事没法标注，只能让它摔 |

## 1. 五个词，一个循环

| 词 | 英文 | 在鸭子上是什么 |
| --- | --- | --- |
| 状态 | state / obs | 身体姿态、14 个关节角、角速度 |
| 动作 | action | 14 个舵机的目标角 |
| 奖励 | reward | 站着 +1，倒了 0，乱抖扣分 |
| 策略 | policy π | 一个函数：看到状态 → 输出动作 |
| 回合 | episode | 从站起来到倒下（或撑满 10 秒） |

整个循环只有一句人话：**策略做动作 → 环境变状态并给分 → 用分去改策略 → 再来一遍**。

还有两个词你一定会遇到：

- **回报 return**：从这一刻起往后所有奖励的折扣和。因为远期奖励不靠谱，要打折（γ，通常 0.95~0.99）。
- **优势 advantage**：这次的表现比"平均水平"好多少。学习时只加强"比平均好"的动作，这是几乎所有算法的核心技巧。

## 2. 三条最容易搞错的规律

**① 奖励是延迟的。** 杆子倒的那一刻才知道前面 20 步里哪一步错了。这是强化学习和"调参"最本质的区别，也是它难的原因。

**② 必须探索，探索就得忍受变笨。** 一直选当前最优动作，就永远发现不了更好的路。所以训练曲线永远是抖的，别指望它单调上升（看第 2 课的图，灰线抖得像心电图，橙线才是趋势）。

**③ 你优化的是回报，不是单步奖励。** 把"每步 +1"改成"活到 10 秒额外 +100"，学出来的行为会完全不同。奖励函数是你写的，所以**你写歪了它就学歪**，这叫 reward hacking。

### 第 1 课：表格法（一定要先跑这个）

**先用网页版走一遍。** 打开 `stepper.html`（或 `./run.sh` 后访问 `/rl-lab/stepper.html`）：
左边是格子世界，右边是这一课的真实代码，点「下一步」走一行，Q 表被改写的瞬间会高亮出来。
支持上一步回退、自动播放、改 α/γ/ε 后重跑、快进 200 回合看策略收敛。

```bash
python3 01_gridworld_qlearning.py
```

故意不装任何库。它会打印一张策略格子图，最后你看到：

```
                     到达率     平均步数    平均回报
  训练前（空表）         14%        27.3      -14.72
  训练后                100%         8.0        9.30
```

**要盯住的一行代码**是脚本里的 `q[state][action] += ALPHA * (target - q[state][action])`。
整个强化学习的最小内核就是这一行：把"实际拿到的"和"原本以为的"差多少，按学习率补一点回去。

### 第 3 课：把你的鸭子接成环境（最重要的一课）

```bash
.venv/bin/python 03_microduck_env.py
```

真实项目里 90% 的工作量在这一步，不在算法。你要写的东西只有五个词：

```python
env.reset()                      # 开局，返回第一个观测
env.step(action)                 # 推进 20ms，返回 obs, reward, done, info
env.observation_space            # 观测几个数、什么范围
env.action_space                 # 动作几个数、什么范围
```

第 3 课的输出很能说明问题：

```
  保持站立姿态           撑了  47 步（ 0.92 秒）  总回报    70.5   倒了
  全程随机乱动           撑了  69 步（ 1.36 秒）  总回报   103.1   倒了
  站立 + 8× 刚度       撑了 500 步（ 9.98 秒）  总回报   750.0   活到超时
```

第三行说明两件事：环境是**可解的**（有策略能撑满 10 秒），
而我能站住是因为我把舵机刚度手工拉到 8 倍——这叫**人肉调参**。
强化学习的意义就是：不手工调这个 8 倍，让程序自己找出来。

**这一课的重点是奖励函数**，抄一遍下面三行，改它，看行为怎么变：

```python
reward = 1.0 + 0.5 * max(upright, 0.0) - 0.02 * np.sum(action**2) / nu
```

- 把 `1.0` 去掉 → 它学会就地躺平（躺着也有 0.5 分，不用费劲）
- 把扣动作分那一项去掉 → 它学会疯狂抽搐（抖也能活着）
- 加上"高度低于 6cm 直接判死" → 它才不敢塌下去

### 第 4 课：PPO 上场（在这台 M3 上实测跑完）

```bash
.venv/bin/python 04_train_duck.py --steps 1000000    # 8 分钟
.venv/bin/python 05_eval_duck.py                     # 10 秒
```

实测学习曲线（`runs/duck_training.png`）：前 1400 个回合死死趴在 47 步的基线上，
看起来像"这算法不行"；到 1500 回合开始爬，1900 回合后稳定贴住 500 步满分。

```
基线（不控制，只给固定角度）：40 步就倒
训练完成，用时 478 秒，共 3500 个回合
  最初 10% 回合平均  40.0 步
  最后 10% 回合平均 500.0 步
```

**第 5 课比第 4 课更重要 —— 它记的是一次真实的翻车。**

第一次训练出来的模型，考试全是满分。但把它在网页里跑起来，鸭子是**拿脑袋撑在地上**的：

```
问题：奖励函数里「站得直」那一项，xmat 的索引写错了
      （Python 里 xmat 是 (nbody, 9)，第 0 行是 world body）
      算出来永远是 1.0，等于这一项根本没起作用
结果：策略学会了用脑袋当第三条腿 ——
      只要躯干高度不跌破 6cm，分数照拿
表现：训练曲线一路满分，鸭子趴着
```

改对那一行、重新训练之后：

```
基线（不控制，只给固定角度）：40 步就倒（0.8 秒）
训练 50 万步：               500 步满分，躯干稳定在 11.5–11.8cm，直立度 1.00
```

同一套代码，只差一个索引。这一课真正的结论：

**奖励函数写歪，训练曲线会骗你；而你看不出来的地方，正是它钻空子的地方。**

## 4. 四周计划（每天 30~45 分钟）

| 周 | 干什么 | 检验标准 |
| --- | --- | --- |
| 第 1 周 | 跑通第 1、2 课；把 `ALPHA` `GAMMA` `EPSILON` 各改一次，看曲线怎么变 | 能用自己的话讲清"为什么必须探索" |
| 第 2 周 | 跑通第 3 课；改奖励函数三项各一次，记录行为变化 | 能说清"为什么它学会了躺平" |
| 第 3 周 | 跑第 4 课；把训练步数从 5 万加到 50 万，画两条曲线对比 | 明白"算力不够时，算法看不出好坏" |
| 第 4 周 | 给鸭子加一个新任务（被推一下后恢复站立 / 原地踏步） | 有一个自己能解释的失败案例 |

## 5. 你这条鸭子线的完整路线

```
① 网页模拟器（已完成）      看得到、能拖、能推倒
② rl-lab/03 环境封装        把 MJCF 变成 obs/action/reward
③ rl-lab/04 PPO 训练        在这里花算力，得到 policy.pt
④ 导出 ONNX                 torch.onnx.export，几十行
⑤ 网页里推理                 onnxruntime-web，20 行 JS
⑥ 回到模拟器                 duck 自己站起来、被推一下能恢复
```

从 ③ 到 ⑥ 的坑：MuJoCo 里 50Hz 决策、网页里也要 50Hz 插值；观测必须和训练时一模一样
（少一个数、顺序错一位，策略立刻变傻）。这是 sim2real 之外最容易翻车的地方。

## 6. 五个必踩的坑

1. **奖励写歪**：它永远会找最省力的作弊方式。第一步永远是先看行为，再看曲线。
2. **观测泄漏**：把"目标位置"直接塞进观测，它学会的是抄答案。
3. **只看平均分**：一定要看方差和成功率，否则一次幸运的高分能骗你一周。
4. **没固定随机种子**：同样的代码两次结果差一倍，先固定 seed 再谈改进。
5. **在真机上期待模拟器的表现**：摩擦、延迟、舵机间隙、电池电压都会让策略崩掉。
